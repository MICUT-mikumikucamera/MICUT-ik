# 민재님 인수인계

## 현재 작업 범위

성윤님 요청 중 모델 정보, 크기 정규화, 발바닥 기준점, 기하 좌표 변환, 카메라 바라보기의 실행 기반을 준비함. 기하의 후보 선택·공간 탐색은 수정하지 않음. IK 알고리즘 완성본은 아니며 기본 서기 연결부터 확인하는 작업물임.

## 먼저 볼 파일

**VRM 직접 렌더 추가:** 새 `3000533088641481097 (1).vrm`은 정상적인 미쿠 VRM 1.0입니다. `npm ci` 후 `tools/render_vrm.mjs`로 Blender 없이 실행할 수 있습니다. `web/vrm.js`가 모델·포즈·발 기준점·카메라·렌더를 담당하고, `web/vrm_math.js`가 입력·좌표 검증을 담당합니다. 기존 Blender 경로도 유지합니다.

1. `examples/model_profile.json`: 원본 .blend의 메시·리그·발 그룹, 목표 키 설정
2. `micut_ik/contracts.py`: 배치 입력 검증, 월드 좌표·투영 계산
3. `micut_ik/blender_adapter.py`: 고정 포즈, 크기·기준점 정규화, 카메라와 렌더
4. `scripts/render.ps1`: Windows 실행 진입점
5. `docs/VALIDATION.md`: 실파일 검사 결과와 남은 한계

## 오늘 이어서 할 작업

1. 새 VRM 또는 .blend를 준비한 뒤 README의 해당 standalone preview 실행. 모델 파일은 별도 전달받아야 함.
2. 생성한 `model_manifest.json`을 성윤님과 공유. 동일한 파일 SHA·키·포즈를 기준으로 배치 공간 검사를 맞춤.
3. `geometry-sample` 검사 보고서를 확인하고 성윤님이 선정한 실제 위치로 교체하여 재실행.
4. 이 Blender 기반으로 계속 진행할지, 기존에 계획한 렌더 엔진으로 교체할지 결정. 엔진을 바꿔도 입력 기준과 manifest 의미는 유지.
5. 이후 양발·골반·손 등의 접촉 목표와 IK 입력을 성윤님과 추가 합의. 앉기·충돌·가림은 별도 작업.

## 원본 모델 관련 주의

처음 제공된 VRM(17,576바이트)은 `Cube` 메시 1개/위치 24개와 휴머노이드 뼈대로 구성됨. 이후 전달된 `(1).vrm`은 30,918,696바이트, 22,530개 정점과 이미지 6개를 포함하며 직접 렌더로 정상 외형 확인. 두 파일을 혼동하지 않음.

VRM 경로는 three-vrm의 표준 휴머노이드 매핑을 사용. Blender 프로필의 MMD식 뼈 이름을 VRM에 그대로 적용하지 않음. 새로운 VRM으로 교체할 때는 외형·휴머노이드·발 가중치를 다시 검증.

## 구현 시 지킬 연결 기준

- 입력 위치는 모델 원점이 아니라 양발의 바닥 접촉점 사이 기준점임.
- 모델 스케일은 profile에서 1회 계산. 카메라 거리나 이미지 크기에 따라 임의 재조정하지 않음.
- 카메라의 실제 높이와 회전은 spatial의 R/t로 적용. `(0,0,0)`을 카메라 위치로 사용하지 않음.
- geometry_world는 좌수계이고 Blender는 우수계임. 단순 축 회전으로만 처리하면 좌우가 반전될 수 있음.
- `stand_default`는 이번 모델 전용 고정 포즈. 리타게팅·일반 IK 지원으로 표시하지 않음.
- 외형 bounding box는 머리카락까지 포함. 몸체 충돌 범위와 분리해야 함.
- 실제 사진 합성 시 깊이 가림·그림자·환경 조명은 아직 없음. flat overlay를 완성 합성으로 제시하지 않음.

## 다음 작업 제안

| 순서 | 작업 | 확인 기준 |
|---|---|---|
| 1 | 성윤님 실제 배치 위치 입력 | 동일 모델 manifest, 단위·방향·기준점 일치 |
| 2 | 포즈·관절 목표 계약 확장 | 어떤 관절이 어떤 표면에 닿는지 명시 |
| 3 | 접촉 IK와 자세 검증 | 발/골반 접촉, 관절 범위, 실패 반환 |
| 4 | 깊이 기반 가림·그림자 | 테이블 앞뒤 관계와 바닥 접지 확인 |

구현 기술은 민재님이 조정 가능. 이 작업으로 Blender를 제품 최종 엔진으로 확정한 것은 아님.
